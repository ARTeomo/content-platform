# TypeScript 7.0.2 to 5.9.3 Downgrade Runbook

**Repository:** `ARTeomo/content-platform`  
**Document Type:** Technical Audit and Migration Runbook  
**Date:** 2026-10-08  
**Scope:** Deterministic, reversible downgrade of the workspace-wide TypeScript toolchain from TypeScript 7.0.2 (native Go-port compiler) to TypeScript 5.9.3 (JavaScript compiler with the compiler API required by `typescript-eslint`) in order to enable type-aware ESLint linting.  
**Execution Environment:** Windows, Git Bash (MINGW64)  
**Status:** Partially executed; migration changes are present on `chore/downgrade-typescript-5.9.3`. Validation is in progress.  
**Source:** Mistral.ai repository audit and migration plan, supplemented with repository-owner execution results recorded on 2026-10-08.

---

## 1. Executive Summary

The project was pinned to **TypeScript 7.0.2** in seven `package.json` manifests and in the pnpm workspace override. TypeScript 7.0 uses the native Go-based compiler implementation and does not provide the JavaScript compiler API required by `typescript-eslint` for type-aware linting. The repository's CI configuration therefore had the lint step deliberately disabled.

**TypeScript 5.9.3 is within the supported TypeScript range of `typescript-eslint` 8.70.0** (`>=4.8.4 <6.1.0`). The downgrade therefore restores the compiler API required by `projectService`-based type-aware linting without requiring an ESLint-stack upgrade or other dependency churn.

The intended migration changes only the TypeScript version and its associated lockfile resolution:

- root `package.json`;
- six workspace `package.json` files;
- `pnpm-workspace.yaml` TypeScript override;
- `pnpm-lock.yaml`.

No TypeScript configuration changes are required. The audit of all 13 `tsconfig*.json` files found no TypeScript-7-specific compiler option.

### Current execution result

The migration has successfully reached the point where:

- TypeScript resolves uniformly to **5.9.3**;
- `pnpm typecheck` passes with zero errors across all six workspaces;
- ESLint 10.10.0 loads successfully;
- type-aware ESLint rules are now actually executing.

However, `pnpm lint` currently reports **138 problems: 118 errors and 20 warnings**. These findings must be treated as real repository lint findings. They cannot currently be classified as regressions introduced by the downgrade, because the same full type-aware lint run was not executable under TypeScript 7.0.2.

Therefore, the migration must **not** claim that the lint baseline is clean. The lint result is instead a newly available repository quality baseline that must be triaged separately from the TypeScript compatibility change.

## 5. Migration Procedure

### Phase 1 — Preconditions and safety checkpoint

```bash
git status --porcelain
node --version
pnpm --version
git rev-parse HEAD
pnpm why -r typescript
pnpm -r exec tsc --version
```

Expected baseline:

- Node.js 22.x;
- pnpm 12.3.4;
- TypeScript 7.0.2 before migration;
- a single resolved TypeScript version.

A dedicated migration branch is used:

```text
chore/downgrade-typescript-5.9.3
```

### Phase 2 — Manifest changes

The seven workspace/root `package.json` files and the workspace override are changed from `7.0.2` to `5.9.3`.

The occurrence-checked replacement procedure was used to prevent unintended edits.

### Phase 3 — Lockfile regeneration

```bash
pnpm install
```

The install regenerates `pnpm-lock.yaml` and executes the repository `postinstall` build.

The resulting lockfile was reviewed for TypeScript-related changes, including the expected removal of TypeScript 7 native-platform package entries.

### Phase 4 — Resolved-version verification

```bash
pnpm -r exec tsc --version
node -p "require('./node_modules/typescript/package.json').version"
pnpm why -r typescript
```

**Result:** all six workspaces resolve TypeScript 5.9.3 and the repository has a single TypeScript version.

### Phase 5 — ESLint verification

```bash
pnpm exec eslint --version
pnpm lint
```

ESLint reports:

```text
ESLint v10.10.0
138 problems (118 errors, 20 warnings)
```

This result is important.

The former TypeScript 7 compiler/API incompatibility no longer prevents ESLint from loading. The current errors are therefore genuine lint findings produced by the repository's active configuration.

**Do not describe these findings as TypeScript-5.9.3 regressions.**

At the same time, **do not describe the lint run as clean**.

Because the complete type-aware lint run was not executable under TypeScript 7.0.2, there is no valid TS 7 baseline against which the 138 findings can be compared.

The appropriate classification is:

> **Newly observable repository lint baseline enabled by the TypeScript 5.9.3 migration.**

The lint findings should be triaged separately by rule, source location, and intended project coding standard.

### Phase 6 — Type checking

```bash
pnpm typecheck
```

**Result: PASS.**

All six workspaces completed type checking with zero errors.

This is the primary compatibility verification for the TypeScript downgrade and demonstrates that the existing source code compiles successfully under TypeScript 5.9.3.

### Phase 7 — Remaining validation

Still required before the migration can be declared fully validated:

```bash

## 6. Lint Findings and Quality-Gate Policy

The TypeScript downgrade has exposed the repository's previously unavailable type-aware lint layer.

Observed categories include, among others:

- `@typescript-eslint/require-await`;
- `@typescript-eslint/consistent-type-imports`;
- `@typescript-eslint/no-unused-vars`;
- `@typescript-eslint/no-unnecessary-type-assertion`;
- `@typescript-eslint/no-floating-promises`;
- project-service parsing issues for JavaScript/module files not included in the current TypeScript project configuration;
- warning-level rules such as explicit function return types and console usage.

These findings should **not** be mass-fixed automatically as part of the TypeScript downgrade.

Recommended procedure:

1. group findings by ESLint rule;
2. determine whether each rule reflects an intentional repository convention;
3. fix source violations where the rule is authoritative;
4. adjust ESLint configuration only where the rule is demonstrably inappropriate;
5. address project-service inclusion/configuration issues separately;
6. rerun the complete lint suite;
7. only then decide whether `pnpm lint` becomes a mandatory CI quality gate.

This keeps the TypeScript migration atomic and prevents an unrelated lint-cleanup effort from being mixed into the compiler downgrade.

## 7. CI and Documentation

The original CI configuration deliberately disabled linting because TypeScript 7.0 was incompatible with the required compiler API.

After the downgrade, the technical blocker has been removed. However, **CI lint should not be re-enabled merely because ESLint now executes** while the repository has 118 lint errors.

The recommended sequence is:

1. complete TypeScript migration validation;
2. document and triage the 138 lint findings;
3. establish the intended lint quality gate;
4. make the required lint/configuration fixes in a dedicated change;
5. re-enable `pnpm lint` in CI once the selected quality gate is green.

`HANDOFF.md` and the CI comments should be updated to remove obsolete TypeScript 7.0.2 compatibility statements once the migration is finalized.

After local validation:

git push -u origin chore/downgrade-typescript-5.9.3
```

The commit is local until the `git push` succeeds. The migration reaches `main` only through the repository's PR/merge workflow.

## 9. Rollback Procedure

Before merge, the migration can be reverted by restoring the working tree and returning to `main`.

Use caution with `git clean -fd`: it permanently removes untracked files.

```bash
git checkout -- .
git clean -fd
git checkout main
git branch -D chore/downgrade-typescript-5.9.3
rm -rf node_modules
pnpm install --frozen-lockfile
```

This restores the original repository manifests and lockfile and reinstalls the TypeScript 7.0.2 dependency tree.
